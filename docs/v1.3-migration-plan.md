# AI CRM V1.0 → V1.3 差异分析与修改计划

> 基线切换：`AI_CRM_V1.3_线索优先_产品需求与交付规范.md` 为唯一有效需求基线，替换 V1.0 PRD。
> 日期：2026-10-10

## 0. 现状盘点（已建 vs 未建）

**已建（#4 基础工程与登录鉴权，经 qa Gate + api 联调 PASS）：**
- 后端：`users` / `user_sessions` / `audit_logs` 三表（迁移 revision `cdff02953343`），Argon2id 密码、HttpOnly Cookie 会话 + CSRF 双提交、登录限流、`/auth/*`、`/admin/users`、`/healthz`、request_id、统一错误信封。
- 前端：登录页、首登改密、路由守卫、Pinia、axios 封装（CSRF/401/错误信封）。
- 部署：compose 四服务、nginx、CI、.env.example。

**未建（关键）：** 无任何业务数据表——V1.0 的线索/客户/商机/跟进/任务切片（#7/#8/#3/#2）从未启动，故**无历史业务数据**。

**结论：兼容迁移 = 纯新增迁移 + 不动已建三表 + 无数据搬迁。** users 表已有数据（管理员种子）保持不动。

## 1. V1.0 → V1.3 差异（核心）

| 维度 | V1.0 | V1.3 | 处理 |
|---|---|---|---|
| 定位 | 通用 ToB CRM | 市场部线索优先管理系统 | 砍商机/任务/销售分配 |
| 角色 | market / sales / admin | market / admin | 弃用 sales（role 为字符串，无需迁移；seed/创建逻辑去掉 sales） |
| 客户 | `customers`（企业档案） | `companies`（轻量，company_id 可空） | 新表 |
| 线索 | `leads`（status: unassigned/pending_contact/following/converted/closed） | `leads`（qualification_status + handoff_status + outcome_status） | 新表，状态机重构 |
| 企业名称 | 必填 | **选填**（可无企业直接录入） | 核心变更 |
| 跟进 | `followups`（phone/wechat） | `lead_activities`（phone/wechat/note） | 新表 |
| 商机 | `opportunities` + 阶段历史 | ❌ 删除 | 不建 |
| 任务 | `tasks` | ❌ 删除 | 不建 |
| 分配 | `lead_assignments`（分配销售） | `lead_handoffs`（交接部门+对接人） | 新表 |
| 反馈 | ❌ 无 | `lead_outcome_events`（推进中/成交/未成交/暂无反馈） | 新表 |
| 来源 | `channel_sources`（单表） | `lead_source_categories` + `lead_source_details`（分类+详情） | 新表 |
| 需求类型 | ❌ 无 | `lead_need_types`（可配置，不等于部门） | 新表 |
| 导入 | `import_batches`/`import_row_results` | `import_jobs`/`import_rows` | 新表 |
| 审计 | `audit_logs` | `audit_logs` + `lead_events`（业务事件前后值） | 新增 lead_events |

## 2. 数据库兼容迁移方案

- **保留不动**：`users`、`user_sessions`、`audit_logs`（revision cdff02953343）。
- **新增迁移 revision 0002**：建 V1.3 全部业务表——`companies`、`contacts`、`lead_source_categories`、`lead_source_details`、`lead_need_types`、`leads`、`lead_activities`、`departments`、`department_contacts`、`lead_handoffs`、`lead_outcome_events`、`lead_events`、`import_jobs`、`import_rows`。
- **users.role 去 sales**：不删字段/不改表，仅在 seed 与创建用户逻辑中不再创建 sales 账号（role 现为 String，兼容）。
- **无破坏性变更**：不 drop、不 truncate、不清空任何现有数据。若未来出现历史数据，先出数据搬迁迁移再改表结构。

## 3. 分模块实施顺序（对齐 V1.3 §11 + 用户 8 项任务）

| 模块 | 内容 | 负责 | 依赖 |
|---|---|---|---|
| M1 文档基线切换 | PRD/architecture/api-contract/decisions 切到 V1.3 | product + architect + api | 无 |
| M2 数据模型与迁移 | 上述 V1.3 业务表 + 字典 + 兼容迁移 | backend | M1 |
| M3 线索统一创建 | 手动+导入建线索，**企业名称可空**，非阻塞企业匹配/关联 | backend + frontend + api | M2 |
| M4 客户管理 | 轻量企业档案 + 一企业多线索 + 合并（管理员） | backend + frontend | M3 |
| M5 快捷跟进 | 列表电话/微信 +1、备注、时间线、幂等撤销 | backend + frontend | M3 |
| M6 判断/交接/反馈 | qualification → handoff（部门+对接人）→ outcome | backend + frontend | M3 |
| M7 数据分析与导出 | 工作台、统计口径、Excel/CSV 导出（受控+防公式注入） | backend + frontend | M5、M6 |
| M8 权限/安全/测试/部署 | 越权测试、E2E、备份恢复、生产加固 | qa + review + deploy | 全部 |

**铁律**：每模块完成后跑测试并修复；先市场部业务闭环，再做 AI 增强（V1.3 AI 降为可选摘要/交接草稿）；禁止擅加销售管道/智能获客等未定义功能；真实 PostgreSQL，禁 Mock 数据。
