# AI CRM V1.3 操作手册

> 面向市场部与管理员的使用说明。关联需求：`docs/PRD-v1.3-source.md`。系统从「线索管理」开始工作；客户档案是系统自动整理的结果，不是录入障碍。

## 1. 角色与权限

| 角色 | 说明 | 主要权限 |
|---|---|---|
| `market` 市场部 | 日常业务入口 | 新建/导入线索、快捷跟进、需求初筛、部门交接、补录反馈、查看全部线索数据、受控导出 |
| `admin` 管理员 | 系统管理 | 上述权限 + 账号管理、部门/对接人、来源与需求字典、企业合并、撤销误操作、审计查看 |

- 无公开注册：账号由管理员创建并设初始密码，登录后强制修改初始密码。
- 所有敏感操作在服务端鉴权，市场部不可修改系统设置或合并企业。

## 2. 登录与首次改密

1. 打开系统地址（HTTPS），输入管理员下发的账号与初始密码。
2. 首次登录系统强制进入「修改密码」页，设置新密码后重新登录。
3. 忘记/锁定账号请联系管理员重置密码。

## 3. 工作台

工作台为登录后首页，展示（均来自真实数据）：

- **指标卡片**：本期新增线索、去重企业、待确认、有效、已交接、暂无反馈、电话总次数、微信记录量、已知成交数。
- **待处理区**：待确认、有效未交接、交接后长期未收到反馈，点击跳转对应线索列表。
- **最近动态**：新建、跟进、判断、交接、反馈、企业关联，显示事件时间与操作人。

## 4. 线索管理（核心）

### 4.1 新建线索

1. 进入「线索管理」→「新建线索」。
2. 填写：获取时间（默认当前，可补录）、姓名（选填）、联系方式（手机号/邮箱/微信至少一种，或有可追溯外部事件 ID）、企业名称（**选填**，无需先建客户）、需求类型、需求描述、来源类型（默认未知）、来源详情、备注。
3. 保存。系统自动检查已有企业，先成功保存线索，再非阻塞提示「可能关联企业」，可忽略暂不处理。

校验底线：不能保存完全无可识别内容的空线索；至少具备「联系方式 / 可识别姓名+来源 / 需求描述+来源 / 可信外部事件引用」之一。

### 4.2 Excel / CSV 导入

1. 「线索管理」→「导入」→ 下载模板。
2. 按模板填写（获取时间、姓名、手机号、邮箱、微信、企业名称、需求类型、需求描述、来源类型、来源详情、备注）。
3. 上传 `.xlsx`/`.csv`，系统预览并反馈逐行校验结果、疑似重复提示、成功/失败/跳过数量。
4. 确认入库。导入不要求先生成企业，成功后走统一业务规则后台匹配客户；重复提交按批次幂等键防重复写入。

### 4.3 快捷跟进

线索列表每行提供「**电话 +1**」「**微信 +1**」「**备注**」「**查看**」「**交接**」：

- 点击「电话 +1」即保存一条电话事件，累计次数 +1（+2/+3 在详情页或展开菜单）。双击/网络重试不重复计数（服务端幂等）。
- 点击「微信 +1」独立记录一条微信事件，不影响电话次数。
- 「备注」可选补充沟通内容，可关联某条事件、补录实际发生时间。
- 列表「最近跟进」「电话累计」「微信记录数」均由有效事件计算，不信任前端累计值。

### 4.4 需求初筛

线索详情「初筛结论」：**待确认**（默认）/ **有效** / **无效**。

- 无效必须填写原因；电话次数不自动变为「有效」。
- 只有「有效」线索才可交接；「待确认」可继续跟进。

### 4.5 部门交接

仅有效线索可交接：

1. 详情「交接」→ 选择业务部门（GDC / Token 供应链 / 润效营，可配置）。
2. 默认对接人可改选，可选填写交接摘要。
3. 确认后记录交接日期与操作人；可授权更正交接并保留历史。

### 4.6 进展反馈

交接后，市场部根据部门反馈补录：**暂无反馈**（默认）/ **推进中** / **已成交** / **未成交**。

- 未收到部门反馈不得推断为「未成交」。
- 最终结果需填反馈依据简述与反馈时间，所有变化留痕。

### 4.7 企业关联

- 保存线索后系统提示候选企业；可「关联」/「解除关联」（需审计）。
- 同名企业合并限管理员，合并前预览影响、保留原始线索快照与审计。

## 5. 客户管理

- 企业列表：企业名称、行业（选填）、联系电话/官网（选填）、关联线索数、最近咨询时间。
- 企业详情：标准名称及别名、联系人（多名）、全部关联线索及来源、历史需求与沟通汇总；点击线索返回其详情。
- 企业档案以自动关联/后台沉淀为主，不强制市场人员日常手工维护；企业字段未齐全不阻碍使用。

## 6. 数据分析与导出

- 默认本月，支持自定义时间范围（界面 Asia/Shanghai 展示，数据库 UTC 存储）。
- 指标：咨询线索数、去重企业数、电话拨打次数、微信跟进事件数、有效/无效/待确认与有效率、部门交接分布、暂无反馈/推进中/赢单/输单数量。
- 来源分析：按来源类型与来源详情（活动名、官网表单等）对比数量、有效数、交接数。
- 各指标标明统计口径（按咨询发生时间/系统创建时间/交接时间/跟进时间/反馈时间）。
- 导出当前筛选数据（含口径说明）；手机号/邮箱导出权限受控并记录审计。

## 7. 系统设置（管理员）

- **用户管理**：创建/禁用账号、重置密码、赋角色（admin/market）。
- **部门与对接人**：维护部门与默认对接人（初始化预置 GDC/同事A、Token 供应链/同事B、润效营/同事C，可编辑启停）。
- **来源管理**：来源分类（线下活动/官网/邮箱/电话/微信/转介绍/其他/未知）与具体来源详情（活动名、表单名等）维护、启停。
- **需求类型**：可配置（如 AI Agent、OPC Team），不自动绑定到某业务部门。
- **审计查看**：关键操作留痕（操作人、时间、对象、变更摘要）。
- **AI 配置（可选）**：仅后端保存 API Key，不对前端公开；AI 未配置或不可用不影响 CRM 基础业务。

> 数据口径提醒：人工记录的电话次数不等于运营商核验通话次数；需求类型不等于业务部门。
